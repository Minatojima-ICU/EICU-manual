# CLIで使うAIコーディングエージェント

> 最終更新: 2026年7月25日

このガイドは、ターミナルからAIコーディングエージェントを利用する人向けです。ターミナルの基本操作と、作業ディレクトリの考え方を理解していることを前提にしています。

ターミナル操作に慣れていない場合は、先に[ターミナルの練習](./terminal_practice.md)を行ってください。

ターミナルではなくアプリから始めたい場合は、[AIコーディングエージェント入門](./vibe_coding_first_step.md)を参照してください。

## 1. 使用するCLIを選ぶ

2026年7月25日現在、このガイドでは次のCLIを扱います。

| CLI | 提供元 | 起動コマンド |
|---|---|---|
| Codex CLI | OpenAI | `codex` |
| Claude Code | Anthropic | `claude` |
| Antigravity CLI | Google | `agy` |

Gemini CLIは提供を終了しているため、このガイドでは扱いません。Google系のCLIを使う場合はAntigravity CLIを選択してください。

料金、無料枠、利用上限、対応OS、認証方法は変更されることがあります。インストール前に、利用するCLIの公式ドキュメントを確認してください。

- [Codex CLI公式ドキュメント](https://developers.openai.com/codex/cli/)
- [Claude Code公式ドキュメント](https://code.claude.com/docs/ja/setup)
- [Antigravity公式ドキュメント](https://antigravity.google/docs/home)

## 2. インストール前の確認

次のコマンドで、現在の環境を確認します。

```bash
pwd
echo "$SHELL"
git --version
node -v
npm -v
```

すべてのCLIがNode.jsや`npm`を必須とするわけではありません。`node`または`npm`が見つからなくても、選択したCLIの公式手順で要求されていなければ問題ありません。

インストール方法は更新される可能性があるため、このファイルには固定のインストールコマンドを記載しません。公式ドキュメントに掲載されている最新のコマンドを使用してください。

グローバルインストール時に権限エラーが出ても、内容を理解せずに`sudo`を付けて再実行しないでください。

## 3. インストールと認証を確認する

インストール後、選択したCLIの確認コマンドを実行します。

```bash
# Codex CLI
codex --version

# Claude Code
claude --version

# Antigravity CLI
agy --version
```

続いてCLIを起動し、画面に従ってログインまたは認証を行います。

```bash
codex
# または
claude
# または
agy
```

サブスクリプションによるログインとAPIキーによる認証は、料金体系が異なる場合があります。APIキーを使用する場合は、従量課金の設定と利用上限を事前に確認してください。

APIキーをシェル履歴、プロンプト、ソースコード、`AGENTS.md`、Git管理対象のファイルへ直接記載しないでください。

## 4. 作業ディレクトリを用意する

AIコーディングエージェントは、起動したディレクトリ内のファイルを読み書きすることがあります。既存の重要なファイルを含まない専用ディレクトリを用意してください。

```bash
mkdir -p vibe_coding_test
cd vibe_coding_test
pwd
```

`pwd`の結果が、作業を許可するディレクトリであることを確認してからCLIを起動します。

ホームディレクトリ、クラウドストレージ全体、複数のプロジェクトを含む親ディレクトリでは起動しないでください。

## 5. CLIを起動する

作業ディレクトリ内で、選択したCLIを起動します。

```bash
# いずれか1つを実行
codex
claude
agy
```

起動後は、最初に現在の作業範囲を確認させます。

```prompt
現在の作業ディレクトリを教えてください。
このディレクトリの外にあるファイルは変更しないでください。
まず、変更せずに現在のファイル一覧だけを確認してください。
```

表示されたディレクトリとファイルが意図した範囲か確認してから、作業を依頼してください。

## 6. 最初の操作

最初は、影響範囲の小さいファイル作成を依頼します。

```prompt
このディレクトリに `cli_test.txt` を作成してください。
内容は `CLI setup completed.` の1行だけにしてください。
作成するファイル以外は変更しないでください。
```

別のターミナル、またはCLIを終了した後に結果を確認します。

```bash
ls -la
cat cli_test.txt
git status --short
```

Git管理されていないディレクトリでは、`git status`がエラーになっても問題ありません。

## 7. 作業を依頼するときの基本

CLIに依頼するときは、次の内容を明示します。

- 目的
- 変更してよいファイルまたはディレクトリ
- 変更してはいけない範囲
- 使用してよいコマンドや技術
- 完了条件
- 実施してほしい確認方法

コマンド実行やファイル変更の承認を求められた場合は、コマンド、対象パス、変更内容を確認してから承認してください。

## 8. 安全上の注意

- 患者情報、個人情報、院内資料、未公開資料を入力しない
- パスワード、APIキー、アクセストークンを入力しない
- 作業前に`pwd`と`git status --short`を確認する
- 意味がわからないコマンドは実行または承認しない
- `rm`、`mv`、`git reset`など、削除や上書きを伴う操作は対象を確認する
- `sudo`や管理者権限を安易に許可しない
- 生成されたコードと実行結果を人間が確認する
- 医療に関する出力は、信頼できる資料と人間による確認を経て利用する

## 9. よくある問題

### `command not found`

インストールが完了していないか、実行ファイルへのパスがシェルに反映されていない可能性があります。

```bash
command -v codex
command -v claude
command -v agy
```

利用するCLIの結果が空の場合は、公式のインストール手順を再確認し、必要に応じてターミナルを開き直してください。

### `permission denied`

対象ファイルやインストール先への権限がない可能性があります。エラーメッセージと対象パスを確認してください。`sudo`を付ける前に、ユーザーが書き込める作業ディレクトリや公式ドキュメントが案内するインストール方法を使用できないか確認します。

### 認証できない

- 使用するアカウントが正しいか確認する
- ブラウザで同じサービスへログインできるか確認する
- 利用可能なプラン、組織の制限、利用上限を確認する
- APIキーを使う場合は、キーの設定方法と課金状態を公式ドキュメントで確認する

### 意図しないファイルが変更された

追加の変更を止め、まず差分を確認します。

```bash
git status --short
git diff
```

変更内容を理解するまで、削除、上書き、コミットを行わないでください。
